# 产品说明

## 一、产品定位

搭子Match 是面向在校大学生的**项目组队与协作匹配平台**。用户通过发布组队帖、浏览广场、发起精准匹配，快速找到技能互补、意向一致、可信度高的项目搭子。

本仓库为该产品的**可运行原型演示**，用于验证交互流程与视觉方案，不包含后端与真实数据。

## 二、目标用户

| 角色 | 典型诉求 |
| --- | --- |
| 组队发起者 | 项目缺人，希望快速找到技能匹配的成员 |
| 组队参与者 | 想加入靠谱项目，担心遇到虚假信息或收费套路 |
| 平台运营 | 处理举报、申诉与违规内容，维护社区秩序 |

## 三、核心价值

1. **多维匹配**：不只按标签匹配，还结合意向方向、技能画像、目标项目与同校权重。
2. **真实可信**：实名认证 + 能力自证（作品集 / 获奖证明 / 项目经历）+ 信誉分体系。
3. **风险可控**：举报、申诉、内容审核三套治理链路，管理端全流程闭环。
4. **低门槛发布**：AI 辅助写作与竞赛选择器，降低发帖成本。

## 四、用户端核心流程

```
隐私政策引导
   └─ 同意并继续
        ├─ 登录（老用户） ──────────────→ 广场
        └─ 注册（新用户）
              └─ 实名认证（姓名 / 学校 / 学号或校园邮箱）
                    └─ 完善资料 Step1 基础信息 → Step2 技能意向 → Step3 目标与权重
                          └─ 广场
```

广场主链路：

```
广场 / 搜索 → 帖子详情 → 发起沟通（聊天）
                    └→ 精准匹配（来源：个人主页 / 帖子 / 手动）
                          └→ 权重设置 → 雷达匹配 → 结果 / 空状态
                                └→ 查看主页 / 发起聊天
发帖 →（AI 帮我写）→ 选择竞赛 → 发布 → 广场同步
```

## 五、管理端场景

| 场景 | 处理方式 |
| --- | --- |
| 用户举报骚扰、诈骗、虚假信息 | 审核中心查看证据 → 忽略（填理由）或封禁并删帖（选违规类型 + 时长 + 是否上报安全中心） |
| 用户对差评提出申诉 | 查看原评价与申诉理由 → 驳回（填原因）或撤销差评（星级归零） |
| 新帖命中敏感词 | 内容审核预览 → 下架（选违规类型）或通过（填备注） |
| 账号治理 | 用户管理检索 → 封禁（原因 + 时长）→ 解除封禁（解封理由） |

## 六、设计语言

| 层级 | 规范 |
| --- | --- |
| 品牌色 | 自然绿 `#2F6B4F`，深绿 `#22503A`，浅茶绿 `#E8F0EB` |
| 页面底色 | 用户端 `#F5F7F5`；管理端 `#F9FAFB`（gray-50） |
| 卡片 | 白底、圆角、极轻阴影、无重边框 |
| 字体层级 | 标题 24~30px / 正文 12~15px / 辅助 11px，字重区分层级 |
| 弹层 | 用户端毛玻璃遮罩 + 圆角 24px；管理端居中 Modal + 遮罩 |
| 状态色 | 正常 绿、封禁中 黄、永久封禁 红 |

## 七、技术架构

```
浏览器
├── React 18 UMD           组件与状态
├── Babel Standalone       浏览器内 JSX 转译
├── Tailwind CDN           原子化样式
├── lucide UMD             图标
└── Mock 常量              所有业务数据
```

两套 Demo 都不依赖构建工具与后端服务：

- 用户端：`src/*.js` 模块化源码 → `scripts/build-user-app.ps1` 拼装为单文件 `index.html`；
- 管理端：`admin.html` 单文件，内含全部组件与路由。

## 八、演示边界

- 所有数据为前端 Mock，刷新页面后恢复初始状态；
- 登录、实名认证、上传附件均为模拟交互，不发起真实请求；
- 图片资源使用 emoji 头像与本地样式，避免外链失效。
